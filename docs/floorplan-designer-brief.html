How to draw a floorplan the interactive plan can read

The plan you draw is not printed. It is loaded into software that finds every stand, reads its number, its size and its name, colours it by whether it is sold, and lets visitors click it. This brief is how to draw so that all of that happens on its own — and how to re-issue a plan once a show has started selling.

1 — What the software reads and what it ignores

Five things are read off the drawing, and nothing else: each stand's shape, its number, its size, the exhibitor name if one is printed, and its fill colour, which says whether it is free, taken or reserved.

Everything else — walls, entrances, aisles, the hall outline, catering, toilets, arrows, the key, your logo — is drawn on screen exactly as you export it, and the software does not try to understand it. Draw it however the plan looks best.

A shape becomes a stand because a stand number sits inside it. Not because of its layer, its colour or its name in the layers panel. That single rule is behind most of what follows: put a number inside a shape and it is a stand; leave it out and it is scenery.

The two things that cannot be fixed afterwards

Text converted to outlines, and one shape drawn across two stands. Both destroy information that is not anywhere else in the file. Everything else in this brief can be corrected on receipt; these two mean a new export.

2 — One stand, one shape the geometry

Each sellable stand is one closed rectangle (or one closed polygon for the odd corner stand). Its edges are the stand's edges. Nothing else about the shape matters to the software, so draw it in whatever style suits the plan.

Do

Draw every stand as its own rectangle, even where a row of stands shares a wall.

Draw to true scale, so a 30 m² stand is drawn as 30 m² of hall.

Delete construction lines, guides and collapsed rectangles before exporting.

Use the rectangle, polygon or pen tool. Rounded corners are fine, and a closed polygon is fine for a corner stand.

Expand symbols, instances and clones into real shapes before exporting.

Don't

Draw a block for a row of stands and divide it with lines on top — that is one stand to the software, with several numbers in it.

Leave an older rectangle underneath a newer one. Two shapes on one footprint is two stands, or a stand the software cannot choose.

Build a stand from four separate lines. An open path has no inside, so no number can sit in it.

Leave a stand as a symbol or a linked instance. It exports as a reference to a shape drawn elsewhere, and the plan has no stand where you drew one.

3 — The three labels number, size, name

Every label is matched to a stand by where it sits: a label belongs to the smallest shape it is inside. So each label sits wholly inside its own stand, in its fixed corner, and never overhangs a neighbour.

Each label is one text object, fully inside the stand it describes.

A small stand whose number does not fit: shrink the type, never let it spill. If it truly cannot fit, leave the size off (the software works it out from the drawing) and keep the number.

Nothing else goes inside a stand

No backing box behind the number, no panel behind the name, no icon or badge within the stand outline. A label belongs to the smallest shape it sits in, so a box tucked behind a number takes that number for itself — and the stand is then recorded as a shape a few centimetres across. It looks perfect on the plan and cannot be clicked. If a number needs to be legible over busy artwork, set it in a darker weight rather than boxing it.

4 — Lounges, theatres, tracks sponsorable areas

A VIP lounge, a networking lounge, a theatre or a conference track is sold to a sponsor, and the software treats it as sponsorable inventory: clickable, with the sponsor's logo drawn onto it once it is taken. It is found the same way a stand is, so draw it like a stand: one closed shape, a number top-left, a size bottom-right, and its name centred — VIP Lounge, Conference Track 1.

What sets it apart from a stand is its fill: one dark colour, used only for these areas and for no more than a handful of shapes on the plan. That is how the software tells a lounge from a sold stand. Catering, toilets and storage are not sponsorable: give them no number and they stay scenery.

5 — Colour one flat fill per meaning

The colours are yours to choose. What the software needs is that every stand with the same meaning has the same flat fill, and no two meanings share one. When the file is received, the person loading it is shown each colour on the plan and what it reads as, and chooses what visitors see on screen — so the plan on the website can keep your palette or not, as the show prefers.

MeaningHow it is recognisedHouse default

Fills on stands are flat and opaque: no gradients, patterns, transparency, blend modes or clipping masks on the stand shapes themselves. A stand whose fill cannot be read is treated as available, and a plan where most cannot be read is refused.

Colour the stand, its layer or its style — all three are read, and a colour set on a layer is inherited by the stands on it. The one thing that is not a colour is none: a stand drawn as an outline with no fill has nothing to say what it is, and is taken as available.

6 — Text and fonts live, always

Never convert text to outlines, curves or paths. Not for the numbers, not for the sizes, not for the names, not "just for the export". A number that has become a shape is gone from the file, and every stand on the plan is then unreadable.

Use any typeface you like. The website replaces the family with its own so the plan matches the rest of the site, and keeps your sizes, weights and positions — so the plan need not carry a font, and a font we do not have is not a problem. Do not paste the numbers in as images, and do not rasterise any part of the drawing; the only bitmaps on the plan are logos, in their own boxes, clear of every stand.

A quick test before sending: open the exported file in a browser and try to select a stand number with the cursor. If it highlights as text, the file is live.

7 — Re-issuing a plan after selling has started

A plan is often redrawn once stands are already sold — a hall extension, a row moved, a block split. The new drawing is laid over the live event without touching a single booking, and that works on one condition: a stand keeps its number from one issue to the next.

The number is how a stand on the new drawing is matched to the stand already sold. Renumber a sold stand and the software sees one stand vanish and a new one appear; the booking stays on the old number and shows nowhere on the map until someone reconciles it by hand.

Ask for the current stand schedule first

Before redrawing a plan that is already selling, ask us for the stand schedule. It is exported from the live event on the day, and it is the only record of what has happened to the layout since your last file: stands merged into a single block, a stand split into cells, a number changed. Redrawing from your own last version instead undoes all of it, and every one of those stands comes back through the check as moved, resized or missing — with a booking underneath. The schedule names each one in its note column.

Do

Keep every existing stand number exactly as it was, whether or not the stand moved or changed size.

Give new stands new numbers — an extension takes the next block (501–540), never numbers freed by a removed stand.

Keep the artboard, the origin and the scale identical to the previous issue, so a stand that did not move is drawn at the same coordinates. A stand is compared to within one drawing unit, so nudging a row to tidy its alignment reports the whole row as moved.

Put the version in the filename and send a short change note: added, removed, moved, renumbered.

Don't

Renumber a row to "tidy up" the sequence.

Reuse a removed stand's number for a new stand.

Re-export at a different artboard size, or with the drawing shifted or rescaled.

Send a changed drawing under the previous version number.

On receipt, the software compares the new drawing to the stands already on the event and shows, before anything is accepted, which stands are new, which have moved or changed size, and which the drawing no longer has — flagging any of those that are sold. A stand the new drawing drops is never deleted if it has a booking; it is kept and listed. So the safest revision is one where that list is empty.

If a sold stand genuinely has to be renumbered

Say so in the change note — old number, new number — before the drawing is loaded. The stand is renumbered on the event first, and the new drawing then matches it.

8 — Exporting SVG, from any tool

The delivery format is SVG. The settings below are what keeps the text live and the geometry readable; anything not listed can stay at its default.

ToolSettings
IllustratorFile → Export → Export As… → SVG. Styling: Internal CSS or Presentation Attributes (either reads). Font: SVG — never "Convert to outlines". Images: Embed. Object IDs: Layer names. Decimal: 2. Minify and Responsive off. Do not use Save As with "Preserve Illustrator Editing Capabilities".
InkscapeSave a copy as Plain SVG. Leave text as text (no Object → Object to Path).
FigmaExport as SVG with "Outline text" switched off. Flatten nothing.
AutoCADExport via PDF or DWG with text as TEXT/MTEXT, then to SVG in Illustrator as above. Text must survive as text at every step.

Groups, layers and transforms are fine — the software resolves them. Rotated stands are fine. What is not fine is anything that turns a number into a picture of a number.

Keep the file under 8 MB; anything larger is refused on upload. It is almost always an embedded logo that takes a plan over: place logos at the size they are drawn rather than embedding the print original.

The file is loaded and checked automatically against specification BEC-FP-01. You will get either a confirmation or a report naming the clauses and the specific stands that need correcting, which can usually be turned around the same day. The report is generated from the file itself, so it is worth running the checks above first.
